# ARTINUS OCR

2026-09 ARTINUS Frontend Engineer 과제용 React Native 앱입니다. 카메라로 촬영한 사진을 처리하고, 사진과 인식 결과를 확인하는 흐름을 구현합니다.

현재는 **모의 OCR 개발 단계**입니다. 클라우드 서비스 인증을 기다리는 동안 카메라와 화면 흐름을 먼저 검증합니다. 표시되는 텍스트와 품질 경고는 고정된 테스트 데이터이며, 실제 사진을 분석한 결과가 아닙니다.

## 실행

Node.js와 플랫폼별 개발 도구(Android SDK·JDK / macOS·Xcode·CocoaPods)가 필요합니다.

```sh
cd apps/mobile
npm ci
cp .env.example .env
npm run typecheck
npm run check
npm run android
# macOS에서 iOS 실행
npm run ios
```

Expo development build를 사용합니다. 네이티브 프로젝트는 Expo 설정으로 생성합니다. 기기 실행은 `npx expo run:ios --device`를 사용합니다. 카메라가 없는 시뮬레이터에서 화면 흐름을 확인하려면 `.env`의 `EXPO_PUBLIC_ENABLE_FIXTURE=true`를 설정하고 Metro를 다시 시작합니다. 이 옵션은 mock 모드에서만 작동하며 화면의 샘플 사진 버튼으로 사용할 수 있습니다.

`EXPO_PUBLIC_*`는 앱에 공개되는 설정입니다. OCR API 키, 서비스 계정 키, 비밀 토큰을 넣지 않습니다. 원격 모드는 서버 계약·인증 구현 전까지 사용할 수 없습니다.

## 선택과 구조

- **React Native + TypeScript**: iOS와 Android에서 화면·상태·오류 계약을 공유합니다.
- **Expo + Expo Camera**: 네이티브 카메라 프리뷰와 정지 이미지 촬영을 사용합니다. 실시간 프레임 OCR은 수행하지 않습니다.
- **Expo Image Manipulator / FileSystem**: 네이티브 이미지 변환으로 긴 변을 제한하고 임시 파일을 관리합니다. 이미지 픽셀이나 base64 데이터를 JS 상태에 보관하지 않습니다.
- **OCR Provider 분리**: 앱은 공통 요청·결과 타입을 사용합니다. 클라우드 서비스 인증 후 중계 API 연결부를 구현합니다. Google Document AI를 검토했으나 서비스 선택과 실제 품질 분석 지원은 연결 시 재확인합니다.
- **명시적 상태 전환**: 촬영·처리·결과·오류를 구분하고, 재촬영으로 취소한 요청의 늦은 응답은 무시합니다. 재시도 가능한 오류는 같은 사진으로 다시 처리합니다.

클라우드 OCR은 네트워크 지연·실패·비용이 있고 사진을 서버에 전송합니다. 실제 연결 시 서버 인증, 호출 제한, 로그에 사진·인식문을 남기지 않는 정책을 구현해야 합니다. 현재는 서버 호출이 없습니다. 앱 내 기록 저장과 텍스트 수정·복사는 범위에서 제외합니다.

## 개발용 시나리오

성공, 텍스트 없음, 품질 경고, 실패 후 같은 사진으로 재시도, 느린 응답, 타임아웃, 취소 후 늦은 응답을 선택할 수 있습니다. 저조도·블러 등의 경고 UI는 모의 데이터로만 검증하며 자동 감지 정확도를 주장하지 않습니다. 기울어진 사진의 인식 품질도 실제 OCR 연결 후 확인합니다.

## 검증

테스트 코드는 최소한으로 유지하고, 핵심 사용자 흐름은 Maestro E2E로 검증합니다. 빌드·자동화 결과는 검증 완료 후 기록합니다.

| 구분 | 상태 |
| --- | --- |
| TypeScript·Expo 의존성 검사·포맷 | 통과 |
| iOS·Android JS/Hermes 번들 생성 | 통과 |
| Android Debug 빌드 | 성공 |
| Android 에뮬레이터 E2E | 일부 단계 확인, ADB 무응답으로 전체 완료 못 함 |
| iOS 시뮬레이터 Debug 빌드 | 성공 |
| iOS 시뮬레이터 E2E | Maestro 3개 흐름 통과 (1분 24초) |
| iPhone 17 Pro 실기기 | 미검증, 사용자 기기에서 진행 예정 |
| Android 실기기 프리뷰·메모리·발열 | 미검증, 에뮬레이터로 대체 검증할 수 없음 |
| 실제 OCR·품질 분석·네트워크 처리 시간 | 서비스 인증 및 연결 후 검증 예정 |

## AI 활용 기록

Codex로 요구사항 정리, 공식 문서·라이브러리 조사, 구현 계획과 앱 코드를 작성합니다. 사용자가 지정한 배정 기준은 복잡한 기반·통합 작업에 GPT-6 Astra, 독립 구현에 GPT-6 Sol xhigh, 단순 정리에 GPT-6 Luna max입니다. 현재 기반·카메라, 결과 화면, 모의 OCR을 파일 범위별로 나눠 병렬 구현하고 메인 에이전트가 통합·검증합니다.

- AI 생성: 초기 앱 기반, 화면, 상태 처리, 모의 OCR, 문서.
- 검증·수정: 모의 제공자의 취소·타이머 정리와 재시도 동작을 에이전트가 확인했습니다. 양쪽 네이티브 빌드와 iOS 시뮬레이터 E2E 3개 흐름을 통과했습니다. iOS 확대 이미지·안전 영역·개발 버튼 겹침 문제는 E2E와 스크린샷을 보고 수정했습니다. Android E2E는 에뮬레이터 무응답으로 완료하지 못했습니다. 사람의 직접 수정·실기기 검증으로 기록하지 않습니다.
- 별도 판단: 실제 서비스 인증을 기다리며 고정 응답으로 UI를 먼저 구현하되, 이를 실제 OCR이나 자동 품질 감지로 표시하지 않기로 했습니다. 테스트는 사용자 요청에 따라 핵심 E2E 위주로 제한합니다.
