# Git 작업 전략

기능 하나를 한 커밋으로 묶고, 그 커밋에 기능 브랜치를 달아 `main`에 순서대로 쌓았습니다. 이력은 선형이라 브랜치마다 "이 기능이 어디서 끝났는지"를 가리킵니다. 되돌아가서 한 기능만 보려면 그 브랜치를 체크아웃하면 됩니다.

## 기능 브랜치

| 브랜치 | 담은 것 |
| --- | --- |
| `docs/assignment-spec` | 과제 스펙, 기술 조사, 구현 계획, 작업 전략 |
| `feat/app-foundation` | Expo 프로젝트 설정, 의존성 잠금, 최소 실행 화면, 공통 타입 |
| `feat/camera-capture` | 카메라 권한·촬영·토치, 사진 변환과 임시 파일 처리 |
| `feat/result-screen` | 결과·오류·품질 경고 화면, 사진 확대 |
| `feat/mock-ocr-flow` | 모의 OCR 제공자, 요청 취소·재시도·타임아웃, 앱 흐름 연결 |
| `test/e2e-maestro` | Maestro E2E, 실행 방법, 검증 기록 |
| `feat/ocr-api` | Cloud Run 중계 함수, 인증·입력 검증·호출 제한, Document AI 호출 |
| `feat/remote-ocr` | 앱의 원격 제공자, 접근 코드 입력 화면 |
| `test/live-verification` | 실제 Google OCR 호출 검증, 배포 한계 기록 |
| `test/unit-boundaries` | 비동기 경계 단위 테스트, 결과 화면 정리 |
| `docs/evaluator-guide` | 심사자용 설치 안내, 평가항목에 맞춘 README 재구성 |

## 커밋 규칙

- 한 커밋이 한 기능을 끝냅니다. 중간 커밋에서도 없는 모듈을 import하지 않습니다.
- 기반 커밋에는 최소 실행 화면을 두고, 기능 연결 커밋에서 완성된 화면으로 바꿉니다.
- 커밋 메시지에는 무엇을 왜 바꿨는지와 어떤 검사를 통과했는지 적습니다. 통과한 검사와 실행하지 못한 검증은 구분합니다.
- 검증 중 찾은 문제는 원인과 영향 범위를 설명하는 수정 커밋으로 남깁니다.
- 로컬에서는 커밋을 정리할 수 있지만 푸시한 `main`의 이력은 바꾸지 않고 강제 푸시도 하지 않습니다.

## 커밋하지 않는 것

`.env`, 자격증명, `node_modules`, Expo가 생성하는 네이티브 프로젝트(`android/`, `ios/`), 빌드·테스트 산출물은 커밋하지 않습니다. `.env.example`과 의존성 잠금 파일은 포함합니다.
