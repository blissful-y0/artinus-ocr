# Git 작업 전략

지금 단계에서는 `main`에 기능별 커밋을 순서대로 쌓고 관련 검증을 마친 묶음을 `origin/main`에 푸시합니다. 별도 기능 브랜치나 PR은 아직 쓰지 않습니다.

## 이번 구현의 커밋 순서

1. 과제 스펙, 리서치, 구현 계획과 작업 전략
2. Expo 프로젝트 설정, 의존성 잠금, 최소 실행 화면과 공통 타입
3. 카메라 권한·촬영·토치 및 사진 변환·임시 파일 처리
4. 결과·오류·품질 경고 화면과 사진 확대
5. 모의 OCR 제공자, 요청 취소·재시도·타임아웃 및 앱 흐름 연결
6. Maestro E2E, 실행 방법과 실제 검증 기록

프로젝트 기반 커밋에는 최소 실행 화면을 두고 기능 연결 커밋에서 완성된 앱으로 교체합니다. 중간 커밋에서도 없는 모듈을 import하지 않습니다. 커밋의 선행 의존성은 위 순서를 따릅니다.

## 이후 작업

- 실제 OCR 중계 API와 앱 연결은 각각 별도 기능 커밋으로 나눕니다.
- 품질 경고 변환·오류 처리는 연결 과정에서 확인한 실제 API 계약에 맞춰 묶습니다.
- 검증 중 발견한 수정은 원인과 영향 범위를 설명하는 수정 커밋으로 남깁니다.
- 로컬에서는 커밋을 정리할 수 있지만 푸시한 `main`의 이력을 바꾸거나 강제 푸시하지 않습니다.
- 변경에 필요한 타입 검사·빌드·E2E만 수행하고 통과한 검사와 실행하지 못한 검증을 구분해 기록합니다.
- `.env`, 자격증명, `node_modules`, 생성된 네이티브 프로젝트와 빌드·테스트 산출물은 커밋하지 않습니다. `.env.example`과 의존성 잠금 파일은 포함합니다.
