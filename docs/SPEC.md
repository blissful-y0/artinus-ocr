# ARTINUS OCR 구현 스펙

상태: 2026-09-29 앱의 원격 OCR 프로바이더와 TypeScript Cloud Run 함수를 구현·배포했고 실제 Document AI OCR 응답을 확인했습니다. 기기별 검증 범위와 품질 분석 한계는 [검증 기록](VALIDATION.md)에, 배포 정보는 [GCP 연결 상태](GCP_SETUP.md)에 기록합니다.

## 확정된 결정 — 2026-09-28

- React Native로 iOS·Android 앱을 구현합니다.
- 카메라 프리뷰에서 촬영한 정지 이미지를 클라우드 OCR로 인식합니다.
- 앱은 GCP Cloud Run function으로 사진을 전송합니다.
- 함수는 TypeScript로 작성하고 Google Document AI Enterprise Document OCR을 호출합니다. enableImageQualityScores 옵션으로 OCR과 품질 분석을 함께 요청합니다. 실제 샘플의 품질과 지연 검증은 채택 확인 단계로 둡니다.
- 앱에 OCR API 키나 서비스 계정 비밀키를 넣지 않습니다.
- 함수가 Document AI에 접근할 때는 연결된 서비스 계정의 권한을 씁니다.
- 앱에는 함수 URL처럼 공개해도 되는 설정만 둡니다. 앱의 .env는 비밀 저장소로 취급하지 않습니다.
- 저조도·블러 경고는 Document AI의 품질 분석 결과를 씁니다. Python·OpenCV 기반 자체 분석과 별도 기울기 판별기는 초기 범위에서 뺍니다.
- 품질이 의심돼도 OCR을 실행하며 결과와 함께 해당 경고와 재촬영 경로를 안내합니다. 품질 검사만으로 인식을 막지는 않습니다.
- 실시간 프리뷰 품질 감지, 자체 자동 보정, 문서 모서리 검출·원근 보정은 초기 범위에서 뺍니다. 엔진의 회전 보정과 기울어진 입력의 인식 결과는 샘플로 검증하고 재촬영 경로를 둡니다.
- iOS는 iPhone 17 Pro, Android는 에뮬레이터로 검증합니다. Android 실기기 성능은 별도 검증 없이 확인했다고 적지 않습니다.

## 요청 흐름

```text
React Native 앱: 프리뷰 → 정지 이미지 촬영
    → Cloud Run function(TypeScript): 요청 검사 → Document AI OCR·품질 분석
    → 앱: 인식 결과·품질 경고 표시 → 사용자 확인·재촬영
```

함수에서 Document AI를 호출할 권한과 앱에서 함수를 호출할 권한은 별개입니다. 함수 주소를 공개해도 된다는 사실이 무제한 호출을 허용한다는 뜻은 아닙니다. 앱 요청에는 평가코드 인증과 인스턴스별 호출 제한을 적용합니다.

## 선택 이유와 trade-off

클라우드 OCR을 쓰면 모바일 OCR 네이티브 라이브러리와 모델을 직접 통합하는 부담이 줄어듭니다. 작은 GCP 함수로 OCR 자격증명을 앱과 분리하고 요청과 오류 처리를 한곳에서 관리합니다.

대신 네트워크 연결, 업로드 지연, 함수와 Document AI 사용량, 배포 유지가 따라옵니다. 촬영한 이미지는 클라우드로 나갑니다. 합성 샘플의 실제 인식은 확인했지만 촬영 사진의 인식 품질과 처리 시간은 더 검증해야 합니다.

## 과제에서 요구하는 완료 기준

- 카메라 프리뷰 → 촬영 → 정지 이미지 OCR → 결과 확인이 가능합니다.
- iOS와 Android에서 같은 기능 흐름을 제공합니다.
- 실기기에서 프리뷰가 끊기지 않고 OCR 처리 과정에서 UI Thread를 blocking하지 않습니다.
- 저조도·블러·기울어진 텍스트처럼 나쁜 입력에도 최소한의 처리를 합니다.
- 카메라 권한 거부와 OCR 실패 같은 오류에 대응합니다.
- 수정·복사는 구현 범위에서 뺍니다.
- README에 기술 선택 이유, trade-off, 한계, 검증 방법과 기기, AI 활용·수정·검증·기각 사례를 기록합니다.

- Document AI 프로세서 버전·언어 설정과 품질 분석 옵션 검증
- GCP 프로젝트·리전·함수 런타임·배포 방법을 확정했습니다. GCP_SETUP.md와 서버 README를 참고하세요.
- 앱에서 함수를 부를 때의 인증, 호출 제한, 요청 형식은 아래 원격 연결 규격을 따릅니다.
- 화면 상태 전환, 중복 요청 방지, 취소, 임시 파일 정리는 구현했습니다. 실기기 검증은 남았습니다.
- 서비스 품질 결함 confidence 0.5 이상을 경고로 바꿉니다. 실제 촬영 샘플과 성능 측정은 더 해야 합니다.

## 자동 감지의 범위와 한계

- 서비스의 품질 점수와 결함 정보를 경고로 바꿉니다. 품질 점수는 OCR 정확도 퍼센트가 아니고 오탐과 누락이 있을 수 있습니다.
- Document AI는 문서 중심이라 문서가 아닌 텍스트 사진도 검증합니다. 품질 분석에 지연이 더 붙으므로 전체 처리 시간을 측정합니다.
- 별도 기울기 감지 결과는 내놓지 않습니다. 기울어진 입력은 엔진 처리 결과, 원본 비교, 재촬영으로 대응하고 부족하면 보완합니다.
- 이미지 방향 정보(EXIF) 처리와 글자 기울기·원근 왜곡은 구분합니다.
- 검사를 서버에서 하므로 촬영 전 경고와 업로드 전 차단은 없습니다.
- 샘플 요청 시간과 경고 전달은 확인했습니다. 실제 촬영의 감지 정확도와 지연 분포는 아직 검증하지 않았습니다.

## 확정된 화면 흐름과 제품 범위

- 촬영 후 사진 확인 단계 없이 바로 업로드하고 OCR을 실행합니다.
- 사진 파일이 준비되면 결과 화면에 촬영 이미지와 처리 상태를 표시합니다.
- 결과 화면에는 사진, 인식 텍스트, 해당 품질 경고를 함께 표시합니다. 사진은 눌러서 확대할 수 있습니다.
- 통신이나 서버가 실패하면 같은 사진으로 재시도하거나 새로 촬영할 수 있습니다. 오류별 재시도 허용 조건은 API 규격에서 정합니다.
- 텍스트가 없는 결과는 요청 실패와 구분하고 재촬영을 안내합니다.
- 품질 경고가 있어도 검출한 텍스트는 표시하며 재촬영할 수 있습니다.
- 처리 중에도 재촬영할 수 있습니다. 기존 작업의 늦은 응답은 새 화면에 반영하지 않습니다. 클라이언트가 요청을 취소해도 서버 OCR이 멈춘다고 보장하지는 않습니다.
- 앱의 현재 사진은 결과 화면에서 재시도할 수 있도록 유지합니다. 결과 화면을 떠나 작업을 끝내면 불필요한 임시 파일을 정리하되 진행 중인 파일 읽기와 충돌하지 않게 구현합니다.
- 앱과 프록시 서버는 사진과 인식 텍스트를 별도 영구 저장소에 저장하지 않습니다. 한 번 처리하고 끝내는 구성입니다. 로그 정책과 외부 OCR 서비스의 데이터 처리 조건은 따로 확인합니다.
- 텍스트 편집·복사, 촬영 기록, 자동 이미지 보정은 구현 범위에서 뺍니다.

위 흐름은 앱에 구현했고 모의 응답으로 검증했습니다. 실제 OCR과 품질 분석을 붙이는 서버 연결 코드도 추가했습니다. 배포와 실제 호출 결과는 검증 기록에서 구분합니다.

## 현재 앱 구현 규칙

- 상태: camera → capturing → processing → success 또는 error. 재촬영은 camera로 돌아갑니다.
- 촬영과 이미지 준비 중에는 중복 입력을 막습니다. 앱이 비활성화되면 카메라를 해제하고 진행 중이던 촬영을 무효화합니다. 이미 시작한 OCR 처리는 결과를 유지합니다.
- 결과 화면을 떠난 요청은 취소 신호와 요청 순번로 무효화합니다. 프로바이더가 취소를 무시해도 이전 응답은 반영하지 않습니다.
- 모의 요청 제한은 10초, 원격 요청 제한은 40초입니다. 서버 HTTP 제한은 35초, Document AI SDK 제한은 25초이고 자동 재시도는 하지 않습니다.
- 사진은 긴 변 최대 2400px, JPEG 품질 0.85로 준비합니다. 이 설정이 작은 글자 인식에 주는 영향은 실제 OCR을 연결한 뒤 검증합니다.
- 원본·변환 중간 파일은 준비가 끝나면 삭제합니다. 결과 사진은 재촬영하거나 화면을 닫을 때 정리하되 프로바이더의 파일 읽기가 끝날 때까지 삭제를 미룹니다. 다음 실행 때는 이전 세션에 남은 캐시를 정리합니다.
- 시나리오 선택은 mock 모드에서만 제공합니다. 샘플 입력은 `__DEV__`와 `EXPO_PUBLIC_ENABLE_FIXTURE=true`를 모두 만족할 때만 제공합니다. remote 모드의 샘플 버튼은 실제 서버로 이미지를 전송합니다.

## 원격 연결 규격 — 2026-09-29

- 시작 화면에서 평가용 접근 코드를 입력합니다. 코드는 React 메모리에만 보관하고 앱 번들·공개 환경변수·영구 저장소에는 넣지 않습니다. Google 비밀키와는 별개인 과제 평가용 인증 수단입니다.
- 서버는 `Authorization: Bearer <코드>`를 상수시간으로 비교합니다. 코드가 틀리면 401이고 앱은 코드 변경 경로를 제공합니다.
- `POST /` 또는 `/ocr`에 `{ requestId, imageBase64, mimeType: "image/jpeg" }`를 보냅니다. 파일 읽기는 네이티브 비동기 API를 씁니다. base64와 JSON 직렬화는 전송 중 JS 메모리를 쓰지만 React 상태에는 보관하지 않습니다.
- 원본 JPEG는 최대 5MiB, JSON 본문은 최대 7MiB입니다. 서버 함수의 용량 검사는 Functions Framework 파싱 이후에 실행됩니다.
- 성공 응답은 `{ requestId, text, warnings, source: "remote" }`입니다. 앱은 형식과 요청 ID, 경고 코드를 검증합니다.
- Document AI 결함 `confidence >= 0.5`는 저조도·블러·반사·작은 글자·잘림 경고로 바꿉니다. 경고가 없다는 사실이 이미지 품질을 보장하지는 않습니다.
- 인스턴스별로 동시 OCR 2건, 60초 동안 10건으로 제한합니다. Cloud Run 최대 인스턴스는 3으로 설정합니다. 평가자 여러 명이 동시에 써도 429가 나지 않게 하려는 값입니다. 인스턴스는 요청이 있을 때만 떠서 유휴 비용이 없습니다. 재시작하거나 새 리비전이 뜨면 카운터가 초기화되므로 비용의 엄격한 상한은 아닙니다.
- 공유 평가코드는 공개 서비스용 사용자 인증이나 기기 검증을 대체하지 않습니다. 평가 기간에만 따로 전달하고 평가가 끝나면 서버를 중지하거나 코드를 교체합니다.
- 서버는 입력 사진, 텍스트, 인증 헤더, SDK 오류 원문을 로그에 남기지 않습니다. 자세한 규격과 한계는 [서버 README](../apps/ocr-api/README.md)에 기록합니다.
