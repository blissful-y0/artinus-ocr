# ARTINUS OCR 구현 스펙

상태: 앱과 모의 OCR 구현 중. 클라우드 서비스 인증을 기다리며 실제 OCR·함수·배포는 보류한다. 아래 GCP/Document AI 내용은 기존 선택안이며, 서비스 연결 시 제공자와 지원 기능을 재확인한다. CLOVA도 대안으로 논의했으나 확정하지 않았다.

## 확정된 결정 — 2026-09-28

- React Native로 iOS·Android 앱을 구현한다.
- 카메라 프리뷰에서 촬영한 정지 이미지를 클라우드 OCR로 인식한다.
- 앱은 GCP Cloud Run function으로 사진을 전송한다.
- 함수는 TypeScript로 작성하고 Google Document AI Enterprise Document OCR을 호출한다. enableImageQualityScores 옵션으로 OCR과 품질 분석을 함께 요청한다. 실제 샘플 품질·지연 검증을 채택 확인 단계로 둔다.
- 앱에 OCR API 키나 서비스 계정 비밀키를 포함하지 않는다.
- 함수에서 Document AI에 접근할 때 연결된 서비스 계정의 권한을 사용한다.
- 앱에는 함수 URL 등 공개 가능한 설정만 둔다. 앱의 .env는 비밀 저장소로 취급하지 않는다.
- 저조도·블러 경고는 Document AI의 품질 분석 결과를 사용한다. Python·OpenCV 기반 자체 분석과 별도 기울기 판별기는 초기 범위에서 제외한다.
- 품질이 의심돼도 OCR을 실행하며, 결과와 함께 해당 경고 및 재촬영 경로를 제공한다. 품질 검사만으로 인식을 차단하지 않는다.
- 실시간 프리뷰 품질 감지, 자체 자동 보정, 문서 모서리 검출·원근 보정은 초기 범위에서 제외한다. 엔진의 회전 보정 및 기울어진 입력의 인식 결과를 샘플로 검증하고 재촬영 경로를 제공한다.
- iOS는 iPhone 17 Pro, Android는 에뮬레이터로 검증한다. Android 실기기 성능은 별도 검증 없이는 확인했다고 기록하지 않는다.

## 요청 흐름

```text
React Native 앱: 프리뷰 → 정지 이미지 촬영
    → Cloud Run function(TypeScript): 요청 검사 → Document AI OCR·품질 분석
    → 앱: 인식 결과·품질 경고 표시 → 사용자 확인·재촬영
```

함수에서 Document AI를 호출할 권한과 앱에서 함수를 호출할 권한은 별개다. 함수 주소가 공개 가능하다는 사실이 무제한 호출을 허용한다는 뜻은 아니며, 앱 요청의 인증·호출 제한은 아래 미결정 항목에서 구체화한다.

## 선택 이유와 trade-off

클라우드 OCR을 사용해 모바일 OCR 네이티브 라이브러리·모델 통합 부담을 줄인다. 작은 GCP 함수로 OCR 자격증명을 앱과 분리하고 요청·오류 처리를 중앙에서 관리한다.

대신 네트워크 연결, 업로드 지연, 함수·Document AI 사용량과 배포 유지가 필요하다. 촬영 이미지는 클라우드로 전송된다. 실제 인식 품질과 처리 시간은 아직 검증하지 않았다.

## 과제에서 요구하는 완료 기준

- 카메라 프리뷰 → 촬영 → 정지 이미지 OCR → 결과 확인이 가능하다.
- iOS·Android에서 동일한 기능 흐름을 제공한다.
- 실기기에서 원활한 프리뷰를 제공하고 OCR 처리 과정에서 UI Thread를 blocking하지 않는다.
- 저조도·블러·기울어진 텍스트 등 나쁜 입력에 대한 최소한의 처리를 제공한다.
- 카메라 권한 거부 및 OCR 실패 등 오류에 대응한다.
- 수정·복사는 구현 범위에서 제외한다.
- README에 기술 선택 이유, trade-off, 한계, 검증 방법·기기, AI 활용·수정·검증·기각 사례를 기록한다.

## 자동 감지의 범위와 한계

- 서비스의 품질 점수와 결함 정보를 경고로 변환한다. 품질 점수는 OCR 정확도 퍼센트가 아니며 오탐과 누락이 있을 수 있다.
- Document AI는 문서 중심이므로 문서 외 텍스트 사진도 검증한다. 품질 분석에 추가 지연이 있어 전체 처리 시간을 측정한다.
- 별도 기울기 감지 결과를 제공하지 않는다. 기울어진 입력은 엔진 처리 결과·원본 비교·재촬영으로 대응하고 부족하면 보완한다.
- 이미지 방향 정보(EXIF) 처리와 글자 기울기·원근 왜곡은 구분한다.
- 서버에서 검사하므로 촬영 전 경고와 업로드 전 차단 기능은 제공하지 않는다.
- 실제 감지 정확도와 처리 시간은 아직 검증하지 않았다.

## 확정된 화면 흐름과 제품 범위

- 촬영 후 별도 사진 확인 단계 없이 바로 업로드·OCR을 실행한다.
- 사진 파일이 준비되면 결과 화면에서 촬영 이미지와 처리 상태를 표시한다.
- 결과 화면에 사진·인식 텍스트·해당 품질 경고를 함께 표시한다. 사진은 눌러서 확대할 수 있다.
- 통신·서버 실패 시 같은 사진으로 재시도하거나 새로 촬영할 수 있다. 오류별 재시도 허용 조건은 API 계약에서 구체화한다.
- 텍스트가 없는 결과는 요청 실패와 구분하고 재촬영을 안내한다.
- 품질 경고가 있어도 검출된 텍스트는 표시하며 재촬영할 수 있다.
- 처리 중에도 재촬영할 수 있다. 기존 작업의 늦은 응답은 새 화면에 반영하지 않는다. 클라이언트 요청 취소가 서버 OCR 중단을 보장하지는 않는다.
- 앱의 현재 사진은 결과 화면에서 재시도할 수 있도록 유지한다. 결과 화면을 떠나 작업을 종료하면 불필요한 임시 파일을 정리하되, 진행 중인 파일 읽기와 충돌하지 않도록 구현한다.
- 앱과 중계 함수에서 사진·인식 텍스트를 별도 영구 저장소에 저장하지 않는 일회성 처리로 구성한다. 로그 정책 및 외부 OCR 서비스의 데이터 처리 조건은 별도로 확인한다.
- 텍스트 편집·복사, 촬영 기록, 자동 이미지 보정은 구현 범위에서 제외한다.

위 흐름의 앱 구현과 모의 응답 검증을 진행한다. 실제 OCR과 자동 품질 분석은 미구현이다. 검증 결과는 README와 검증 기록에서 구분한다.

## 현재 앱 구현 계약

- 상태: camera → capturing → processing → success 또는 error. 재촬영은 camera로 돌아간다.
- 촬영·이미지 준비 중 중복 입력을 막고, 앱이 비활성화되면 카메라를 해제하고 진행 중 촬영을 무효화한다. 이미 시작한 OCR 처리는 결과를 유지한다.
- 결과 화면을 떠난 요청은 취소 신호와 요청 세대 번호로 무효화한다. 제공자가 취소를 무시해도 이전 응답을 반영하지 않는다.
- 모의 요청 제한은 10초다. 실제 서비스의 제한은 연결 후 측정해 정한다.
- 사진은 긴 변 최대 2400px, JPEG 품질 0.85로 준비한다. 이 설정의 작은 글자 인식 영향은 실제 OCR 연결 후 검증한다.
- 원본·변환 중간 파일은 준비 후 삭제한다. 결과 사진은 재촬영·화면 종료 시 정리하되 제공자의 파일 읽기가 종료될 때까지 삭제를 미룬다. 다음 실행 시 이전 세션 잔여 캐시를 정리한다.
- mock 모드에서만 시나리오 선택과 선택적 샘플 입력을 제공한다. remote 모드는 인증된 중계 API를 구현하기 전 설정 오류로 종료한다.
